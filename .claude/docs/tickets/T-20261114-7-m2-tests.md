### Agreed API (tests import exactly these; implementers must match)

`src/layout.ts`
```ts
export const CELL_W = 240, CELL_H = 200, MARGIN = 60, ICON_SIZE = 96, GROUP_PAD = 36;
export interface Rect { x: number; y: number; width: number; height: number }
export interface Layout {
  width: number; height: number;                       // whole canvas in px
  nodes: Record<string, { x: number; y: number }>;     // node CENTER in px
  groups: Record<string, Rect>;                        // group rectangle in px
}
export function layoutScene(scene: Scene): Layout;
```
- `at: [col, row]` on a node is a grid cell (numbers, fractions allowed). Centre in px:
  `x = MARGIN + col * CELL_W + CELL_W / 2`, `y = MARGIN + row * CELL_H + CELL_H / 2`.
  A node with `at` is never moved. Nodes without `at` are placed automatically.
- Automatic placement: deterministic. Column = breadth-first depth over `links` (undirected) from the
  first declared node; nodes in a component not reachable from it start in the columns after the last
  used one. Rows are integers, normalised so the smallest row is 0. No two auto-placed nodes share a
  cell. Same input gives the same output (run twice, deep equal).
- Canvas: `width = 2 * MARGIN + (maxCol + 1) * CELL_W`, `height = 2 * MARGIN + (maxRow + 1) * CELL_H`
  over all nodes (use the largest used col and row, rounded up for fractions).
- Group rectangle: bounding box of the member node centres, grown by `ICON_SIZE / 2 + GROUP_PAD` on
  every side and by a further `24` px on top for the group label.
- Example scene `examples/webrtc.scene.yaml` (load with `loadScene`): `client` is in column 0,
  `sam` is in a later column than `r2`, `client` to `r1` to `net` are in strictly increasing columns,
  and NO node that is not a member of group `sams-home` has its centre inside the group rectangle.
  Canvas contains every node centre and every group rectangle.

`src/icons.ts`
```ts
export interface Icon { name: string; width: number; height: number; viewBox: string; body: string }
export function iconNames(): string[];     // sorted, from icons/isoflow/*.svg
export function loadIcon(name: string): Icon;
```
- `body` is the inner markup of the root `<svg>`: no `<?xml`, no comment, no root `<svg>` tag.
- Every `id="X"` becomes `id="<name>__X"` and every reference to it (`url(#X)`, `href="#X"`,
  `xlink:href="#X"`) is rewritten to match, so two icons never share an id.
- `width`/`height` are taken from the viewBox. Unknown or unsafe names (`../x`, `a/b`, empty, upper
  case, not in `iconNames()`) throw an error that includes the name and lists no file path.

`src/render.ts`
```ts
export function renderSvg(scene: Scene, layout: Layout, opts?: { icons?: (name: string) => Icon }): string;
```
- Returns one SVG string, no animation. Default `icons` is `loadIcon`.
- Structure (tests check it with a small DOM-free parser or regex, and with snapshots):
  ```
  <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H" role="img" aria-label="<title>">
    <title>scene title</title>
    <defs> one <symbol id="icon-<name>" viewBox="..."> per USED icon, sorted by name </defs>
    <g class="groups"> <g data-group="<id>"><rect .../><text class="group-label">..</text></g> ... </g>
    <g class="links">  <line data-link="<a>--<b>" x1 y1 x2 y2 /> one per link, centre to centre </g>
    <g class="nodes">  <g data-node="<id>" transform="translate(x,y)">
        <use href="#icon-<name>" x y width height (ICON_SIZE box centred on 0,0) />
        <text class="label">..</text> [<text class="sub">..</text> only if `sub` is set]
    </g> ... </g>
  </svg>
  ```
- Document order: groups, then links, then nodes (so nodes paint on top). Nodes and groups in
  declaration order.
- All text and attribute values are XML-escaped (`&`, `<`, `>`, `"`, `'`), for example the label
  `Sam's laptop` and a title containing `&`.
- The icon used by two nodes appears once in `<defs>`.
