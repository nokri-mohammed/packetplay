## Goal

## Spec

- New exported constants in `src/player-core.ts`: `SHAKE_MS = 450`, `SHAKE_AMP = 5` (world px),
  `SHAKE_CYCLES = 4`.
- New exported pure helper `nodeShake(t: number, atMs: number): { dx: number; dy: number }`:
  zero outside `[atMs, atMs + SHAKE_MS]`; inside it, with `u = (t - atMs) / SHAKE_MS`,
  `dx = SHAKE_AMP * (1 - u) * sin(2 * PI * SHAKE_CYCLES * u)` and `dy = 0` (a horizontal damped shake;
  zero at `u = 0` and `u = 1`). Exact unit tests (before, at start, a quarter of a cycle, middle, end,
  after) with values computed by hand.
- Shake events (derived from the timeline, not stored): for every hop of every packet-mode step, the
  arrival node shakes from `hop.endMs` (the destination of the hop). For a step with `typing`, the
  source node shakes from `startMs + typing.length * TYPE_CHAR_MS` (the moment Enter flashes). Flow
  steps: no shake. Add one pure helper `shakeEvents(tl: Timeline): Map<string, number[]>` (node id to
  start times, ascending) and test it on a small fixture and on the website example (the source node
  `client` has the Enter event; every node on a route has an arrival event). The shake offset of a node at
  time `t` is that of the latest event with `atMs <= t` (events never overlap by more than one shake; if
  they do, the later one wins).
- Player: apply `translate(dx dy)` to the node group (keep any scale from the reveal pop: compose them in
  one transform string, translate first, same pivot as the pop). Remove the transform when both are
  zero. Pure function of the clock time, so pause and seeking work. Reduced motion: no shake.
- Dot on the other side: in `frameAt` (`src/player-core.ts`), during the rest after a hop that has a next
  hop in the same step, the packet sits at the near edge (`hop.x2,y2`) while `t < hop.endMs + SHAKE_MS`
  and at the far edge of the next hop (`nextHop.x1,y1`) from `hop.endMs + SHAKE_MS` until the next hop
  starts. The balloon and the data rows follow the dot. After the last hop of a step the packet stays at
  the near edge for the whole rest (there is no other side). Direction, data and everything else in the
  packet position stay as they are. `SHAKE_MS` (450) is shorter than `NODE_DWELL_MS` (650), so the dot is
  on the far side for 200 ms before it moves.
- Update tests that encode rest positions (for example in `test/timeline-lanes.test.ts`) with exact
  values; add exact tests for the two positions during a rest and for the last hop. State one hand
  calculation of a rest in the Report.

Hand calculations (all asserted exactly in the tests):

- Quarter cycle: one cycle is 450 / 4 = 112.5 ms, so a quarter is u = 1/16, sin(pi/2) = 1, dx = 5 * (15/16) = 4.6875.
  Three quarters: u = 3/16, sin(3pi/2) = -1, dx = -5 * (13/16) = -4.0625. Middle u = 0.5: sin(4pi) = 0.
- Rest (fixture a, b, c at x 0, 200, 400, step a to c with typing "abc"): typingMs = 3 * 80 + 500 = 740;
  hop 0 runs 740 to 1840, hop 1 starts 740 + 1750 = 2490. Rest after hop 0 is 1840 to 2490 (650 ms).
  Near edge x = 200 - 44 = 156 while t < 1840 + 450 = 2290; far edge x = 200 + 44 = 244 for 2290 to 2490
  (200 ms), then hop 1 starts at 244. Shake events: a at 240 (3 * 80), b at 1840, c at 740 + 1750 + 1100 = 3590.
  After the last hop the dot stays at 400 - 44 = 356 for the whole rest.

Notes: the existing rest tests (`test/timeline-lanes.test.ts`, t = 1500, 1100 + 450 = 1550 is later) still hold
unchanged, so no old test needed editing. For a `both` step only the forward packet jumps to the far side; the
return packet keeps its position (the spec named only the packet). The shake also applies to hidden nodes' groups
in the same transform string as the reveal pop.

Lessons:

- Shake must be a pure function of the clock (latest event at or before t), so seeking and pause need no state.
- Node groups carry a `translate(cx,cy)` transform, so a shake or pop must be appended to the original string, with
  translate before scale, never replace it.
- Choose test times away from event boundaries by one millisecond (2289 vs 2290) to pin the exact switch.
- A `both` step's return packet does not get the far-side jump; revisit if the CEO wants it symmetric. (T-20261114-25)
