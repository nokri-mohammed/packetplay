### Send path (from the CEO)

- 7 Application, who: browser / Node. notes.txt (4000 bytes) put in an HTTP POST: [HTTP headers][4000
  bytes]. `send()` hands the bytes to the kernel.
- 4 Transport, who: kernel. TCP splits the stream into segments (max about 1460 bytes of data each) and
  adds a TCP header (ports, sequence number): [TCP|1460] [TCP|1460] [TCP|1080].
- 3 Network, who: kernel. IP adds a header to each segment (source IP, destination IP) = 3 packets.
- 2 Data link, who: NIC + driver. Ethernet adds a MAC header and a CRC = 3 frames [ETH|IP|TCP|1460|CRC].
- 1 Physical, who: NIC (PHY). Preamble + frame bytes become bits (10101010...10101011, 0110 1001 ...),
  then a signal on the wire: voltage (copper), light (fibre) or radio (WiFi).

### Receive path (from the CEO)

- 1 Physical (NIC PHY): signal on the wire becomes bits.
- 2 Data link (NIC + driver): find the start marker, cut frames, check CRC, check the destination MAC is
  mine, strip the Ethernet header. Frames are copied to RAM (DMA). An interrupt says "frames are ready".
- 3 Network (kernel): IP checks the destination IP is mine, strips the IP header, giving 3 segments.
- 4 Transport (kernel): TCP matches each segment to its connection (IPs + ports), uses sequence numbers
  to put them in order, sends ACKs, strips the TCP header, puts the bytes in the socket receive buffer
  (1460 + 1460 + 1080 = 4000 bytes). The app reads them (Node `data` event).
- 7 Application (Node / server): the HTTP parser reads the headers, then the 4000-byte body is
  notes.txt, rebuilt.

Groups: the schema supports them (top-level `groups` map of id to `{ label }`, and a node's `group` field),
as `examples/webrtc.scene.yaml` does. Declared `user` (app), `kernel` (tcp, ip), `hardware` (link, phys).

Layout seen (`layoutScene`): the 5 nodes sit on one diagonal row at j=0, i = 0, 2, 4, 6, 8 (app, tcp, ip, link,
phys). Group rects (tile units, pad 1): user i -1..1, kernel i 1..5, hardware i 5..9, all j -1..1. So the three
groups are adjacent and share the edges at i=1 and i=5, and the user/kernel and kernel/hardware boundaries are
drawn as a common line. No overlap, no node outside its own group.

Lessons:
- In YAML, a plain `desc:` value must not contain `: ` (colon plus space), or the parser fails with "Nested
  mappings are not allowed in compact mappings". Use parentheses or quote the value.
- Groups on a chain of nodes come out as adjacent bands sharing an edge, which suits a user space / kernel /
  hardware boundary.
